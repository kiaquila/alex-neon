# AGENTS.md — Alex Neon

Редизайн действующего лендинга «ИИ по делу» (Алексей Грищенко) под концепцией
**Alex Neon**. Контент перенесён дословно; новизна — только дизайн и подача.

## Базовые стандарты

Репозиторий подключён к общему baseline `kiaquila/web-design` (профиль
`static-cloudflare`, см. `.web-design/project.json` и `.web-design/lock.json`).
Перед изменениями читать `docs/standards/` — эти документы managed'ы baseline'ом
и обновляются только через review-PR. Правила ниже уточняют общие стандарты и не
имеют права их ослаблять.

## Идентичность

- Тема тёмная: почти чёрный фон, светлый текст, много воздуха.
- Единственный акцент — градиент лазурно-бирюзовый → фиолетовый. Неон дозируется:
  CTA, ключевые подсветки, нейро-фигура. Никакого «градиентного супа», третьих
  цветов и светящихся рамок на каждом блоке.
- Типографика: Unbounded — только дисплейные роли (h1, h2, номера, монограмма);
  Manrope — весь остальной текст. Обе variable, self-hosted, subsets
  cyrillic+latin. Новые шрифты не добавлять.
- Знак бренда — логотип **ALEX OXITOCIN** только в шапке: «ALEX» лазурный
  `--teal`, «OXITOCIN» фиолетовый `--logo-violet`. Начертание перерисовано по
  образцу заказчика; не менять буквы, порядок цветов и пропорции без запроса.
  Ссылке нужен `aria-label`, самой графике — `aria-hidden`.
- Логотип лежит в `<defs>` как обычная `<g>`, а не как `<symbol>`: `<use>` даёт
  символу собственный вьюпорт в точке (0,0), из-за чего рисунок съезжает
  относительно viewBox с отрицательным началом и последняя буква оказывается
  подрезанной. Отступ в viewBox должен быть не меньше половины толщины штриха —
  это проверяется тестом.
- В футере «© Alex Oxitocin» остаётся серым текстом; напротив него стоит только
  светлая подпись разработчика **KS Design**, ведущая на
  `https://ks-design.art/`. Логотип ALEX OXITOCIN и слоганы туда не возвращать.
- Тон: инженерный, спокойный, дорогой. Без восклицаний, таймеров срочности и
  фейковых счётчиков.

## Контент

- Источник истины — `./CONTENT-AUDIT.md`. Текст, порядок секций, якорные id,
  внешние ссылки и метаданные переносятся посимвольно (включая «ёлочки», „лапки",
  тире и `·`). Русский текст в HTML — сырым UTF-8, без HTML-сущностей.
- Не выдумывать факты, цены, отзывы, логотипы, сроки. Видео-блок — заглушка.
- Изменение контента — только по подтверждению заказчика с записью в
  `CONTENT-AUDIT.md`.

## Реализация

- Статика без фреймворков: `website/src/index.html`, `src/404.html`, пять слоёв
  стилей `src/styles/{tokens,base,layout,components,sections}.css` (конкатенация
  в этом порядке; `components.css` — переиспользуемые примитивы, `sections.css`
  — блоки конкретных секций). Скрипты: `src/js/site.js` (классический),
  `src/js/field.js` — общий генератор поля без DOM, `src/js/palette.js` —
  цветовые вёдра и glow-спрайты, считаются один раз на импорте,
  `src/js/placement.js` — геометрия фигуры на канвасе, `src/js/neural.js` —
  рендер и взаимодействие (ES-модули, подключается `type="module"`). Файл кода
  — не более 600 строк; при превышении слой делится по смыслу, а не сжимается.
  Главное ограничение для `.js` в `dist` — суммарно 20 КБ в gzip: это объём,
  который получает пользователь. Потолок в 48 КБ без сжатия вторичен и
  защищает от случайного раздувания, не вынуждая сокращать комментарии,
  объясняющие причины решений.
- Слои стилей склеиваются по порядку, поэтому адаптив компонента живёт в его
  собственном слое: медиазапрос в `layout.css` не переопределит правило из
  `components.css`.
- Расширения скриптов — `.js`, даже для модулей: `.mjs` зависит от MIME-типа
  хостинга, а браузер определяет модуль по атрибуту `type`.
- Никаких внешних origin'ов: ни CDN, ни аналитики, ни внешних шрифтов/картинок.
  CSP воркера: `script-src 'self'`; инлайновых `<script>` нет; `style`-атрибуты
  допустимы только для CSS-переменных.
- Страница обязана быть читаемой и рабочей без JavaScript: контент не прячется
  до инициализации, FAQ — нативные `<details>/<summary>`, навигация — якоря.
- Доступность: контраст AA на тёмном фоне, `:focus-visible` заметен, tap-цели
  ≥ 44 px, один `h1`, осмысленные лендмарки, `lang="ru"`.

## Нейро-поля (hero и «Как проходит»)

- Оба поля — `<canvas>` с `aria-hidden="true"`, `pointer-events: none`;
  слушатели на секции-хосте. Геометрия задаётся CSS-переменными на канвасе:
  `--nx`/`--ny` — центр, `--nrx`/`--nry` — полуоси, всё в долях канваса.
  Композиция остаётся решением стилей, а не кода.
- Фигура статична и построена как дендритное дерево: из ядра (несколько сом,
  сплетённых между собой) расходятся нити, которые сохраняют кривизну и потому
  читаются как дуги, ветвятся и заканчиваются сомой. Никакого вращения и
  дрейфа. Не превращать поле ни в равномерную «пыль частиц», ни в звёздочку из
  прямых лучей из одной точки.
- В hero фигура — круг: `--nr` задаёт радиус долей высоты канваса, шаги внутри
  длиннее, чем у края, поэтому середина круга разреженнее обода, а сам обод
  дорисован прерывистым кольцом (`rim`). Круг не имеет права заезжать на текст:
  `keepRightOf` центрирует его в свободной колонке рядом с копией и уменьшает
  радиус, пока край не разойдётся и с текстом, и с краем канваса. Потолок для
  верха круга зависит от раскладки, и её спрашивают, а не угадывают: рядом с
  копией мешает только шапка (`keepBelow`), а в одну колонку над кругом стоит
  сама копия (`keepBelowStacked`) — сколько её, зависит от высоты телефона.
  Геометрия живёт в `js/placement.js`: файл отвечает на свой вопрос — «где
  фигура», тогда как `neural.js` отвечает «что она делает». Он же чистый
  настолько, что дуга проверяется тестом, а не глазом.
  В одну колонку центр стоит ровно на нижней грани канваса (`--ny: 1`), поэтому
  видна ровно верхняя половина сферы — полусфера, а не бугорок. На телефоне hero
  не привязан к высоте viewport: под копией резервируется контентная полоса из
  зазора и радиуса `0.62` ширины. Поэтому сворачивание панелей Safari при скролле
  не меняет геометрию, а запускает только свечение. Множитель ширины 0.62, а не
  0.5: радиус в половину ширины оставил бы над куполом мёртвое поле. Срезаются
  только «плечи» сферы — дальше срез снова превращает её в плоскую дугу.
  Бюджет узлов там отдельный (`densityStacked`) и считается **по площади самого
  диска**, а не канваса, со ставкой, уже включающей удвоение за скрытую половину.
  Площадь канваса — честная мера, только пока фигура его заполняет; в stacked-
  раскладке бюджет поэтому остаётся привязан к площади самого диска. Нижний
  порог числа узлов там тоже ниже и не отменяет масштабирование.
  Три буллета hero в этой раскладке скрыты, чтобы освободить полосу; решение
  заказчика, записано в `./CONTENT-AUDIT.md`.
- На тач-экранах нет наведения, поэтому hero сам себя подсвечивает:
  `ambientEvery` раз в несколько секунд (с джиттером) зажигает один видимый
  нейрон, и заряд дальше идёт по связям обычным путём. Фигура при этом
  по-прежнему не движется. Импульсы проходят через `ambientDue()` — единственный
  гейт: только `hover: none`, только не при `prefers-reduced-motion`, только
  пока поле не «спит». `stop()` обязан гасить и отложенный таймер, иначе поле
  разбудит себя за кадром. Между импульсами цикл простаивает, поэтому rAF занят
  примерно четверть времени, а не постоянно.
- Там же купол отвечает на скролл (`scrollDriven`): пройденная героем доля пути
  задаёт угол на ободе, и заряд идёт внутрь оттуда — свет проходит по дуге.
  Слушатель обязан быть `passive` и только поднимать флаг; чтение геометрии и
  впрыск делает уже запланированный кадр, иначе быстрый флик стоил бы впрыска
  на каждое событие скролла. Гейты те же, что у импульсов.
- `touchGlow` усиливает свечение только при `hover: none`: на телефоне фигура
  мельче и зажигается одиночными зёрнами, а не курсором, который на ней стоит.
  Мышь получает немасштабированную сферу — иначе десктоп засветится.
- Узлы обязаны быть разного размера: вдоль нити — почти невидимые, на
  развилках — бусины, на концах — заметные сомы с широким разбросом. Нить,
  вышедшая за границу эллипса, всё равно получает сому, иначе у фигуры не
  будет видимых окончаний.
- Загораться может любой нейрон: энергия впрыскивается вокруг курсора и
  дальше идёт по связям, затухая примерно за секунду. Связь светится, когда
  заряд идёт по ней.
- В блоке «Как проходит» ядра привязаны к пунктам (`anchors`), чтобы наведение
  на любой шаг всегда подсвечивало его нейрон. Базовый слой там приглушён
  (`baseOpacity`), потому что лежит под текстом. Бюджет узлов раздаётся ядрам
  по кругу — иначе последние шаги остаются без дендритов.
- Сторона с текстом прореживается сильнее (`leftBias`): нити, нацеленные туда,
  не выпускаются вовсе, а забредшие — обрываются. Пустота там читается лучше,
  чем более бледный мусор.
- Зазор до копии — часть геометрии, поэтому `ResizeObserver` следит и за самим
  keep-out элементом, а его высота входит в проверку «что-то изменилось».
  Шрифты подключены с `font-display: swap`: первый замер может лечь на
  метрики запасного шрифта, а когда придут Unbounded и Manrope, копия
  переверстается и подрастёт. Наблюдение за копией сохраняет зазор и синхронно
  обновляет высоту контентной полосы.
- Производительность: DPR ≤ 2, бюджет узлов по площади, базовый слой
  рендерится один раз в offscreen-canvas, rAF идёт только пока есть энергия и
  останавливается вне вьюпорта и при скрытой вкладке; ресайз — с дебаунсом.
  Событие указателя считается доказательством видимости и снимает залипшее
  состояние «вне экрана».
- `prefers-reduced-motion: reduce` — только статичный рендер, без цикла.

## Проверки

Из корня репозитория:

```bash
npm run preflight
npm run project:check
```

Тесты (`website/tests/site.test.mjs`) проверяют дословность контента, якоря,
отсутствие неразрешённых внешних URL, reduced-motion в `neural.js`,
`:focus-visible`, локальные шрифты и служебные файлы стенда. Не ослаблять тесты
ради прохождения.

Визуально: 360 px и 1280 px+, фокус с клавиатуры, FAQ, hover/touch нейронов,
`prefers-reduced-motion`, консоль без ошибок.
